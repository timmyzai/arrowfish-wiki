主要漏斗Main Funnel

  • 下载 → 启动：渠道（Google Play / 官网 / 华为）；渠道事件首次注册时上报一次（详见 PRD 推荐章节）
  • 启动 → 注册：免密注册（一键，单个 /user/auto-register）或正式注册（手机号 / 邮箱 + 密码）
  • 注册 → 首次连接：默认线路自动选择，跳过线路选择减少流失
  • 免费连接 → 看广告 / 付费：免费每天 30 分钟，看广告再加 30 分钟（每天最多 2 次）
  • 付费首单 → 续费：续费由 IAP 自动续订（Google Play / Apple）或微信 / 支付宝 / USDT 手动续
  • 付费 → 升级专线：高客单价品类，需要后台分配节点
  • Download → Launch: channels (Google Play / official site / Huawei); channel events fire once at first registration (see PRD referral chapter)
  • Launch → Register: passwordless (one-tap, single /user/auto-register) or full sign-up (phone / email + password)
  • Register → First Connect: default line auto-selected to skip line picker and reduce drop-off
  • Free Connect → Ad / Paid: free 30 min/day; +30 min per ad watched (max 2/day)
  • First Order → Renew: auto-renewal via IAP (Google Play / Apple) or manual via WeChat / Alipay / USDT
  • Paid → Dedicated Upgrade: high-ARPU category; requires admin to allocate a node

客服操作要点Support quick reference

  • 确认账号：后台搜索用户 ID / 邮箱 / 手机号。专线绑定信息在用户详情页「专线」标签
  • 分配延迟：自动分配是 1 分钟内的定时任务；下单后 60 秒内还没看到线路是正常的，超过 5 分钟未分配请上报
  • 节点不可用：用户专线节点出问题时，运维侧的「节点健康状态机」会自动剔除轮换；客服需要做的是记录受影响的用户列表并告知用户预计恢复时间
  • Find the account: search admin by user ID / email / phone. Dedicated bindings live under the user-detail "Dedicated" tab
  • Assignment lag: auto-assign is a 1-min cron; missing line within 60 s is expected; report if not assigned after 5 min
  • Node unhealthy: ops-side health state machine auto-removes from rotation; support's job is to log impacted users and inform them of ETA

已知支付场景Known payment scenarios

  • 支付成功但 App 没刷新：v3.7.0 之前的版本可能出现，重新登录后看到 VIP 已生效。这是客户端展示问题，不是支付失败。后端日志可查证扣款是否完成
  • 第二个月续订没生效（已修复）：续订代币推进 bug 导致 IAP 第二月续订无法验证，2026-05 第3阶段已修复。如收到 2026-04 之前的相关投诉，按客服补发流程处理
  • USDT 转账迟迟未到账：先看链上确认数（TRC20 ≥ 19 个，ERC20 ≥ 12 个）；超过预计时长仍未到账才上报后端
  • Paid but app not refreshing: pre-v3.7.0 may show stale state; user re-login surfaces VIP. This is a display bug, not a payment failure — backend logs confirm settlement
  • Month-2 IAP renewal not granted (fixed): token-advance bug blocked verification on month-2 renewals; fixed Sprint 3 (May 2026). For complaints dated before 2026-04, follow standard reissue flow
  • USDT settlement slow: check chain confirmations first (TRC20 ≥ 19, ERC20 ≥ 12); only escalate if past expected window

六、抽奖 · 优惠券 · 推荐机制6. Lottery · Coupons · Referral

抽奖（在线时长奖励）Lottery (online-time reward)

  • 规则：免费用户每天连接 VPN 一段时长后获得抽奖资格；奖品池含会员时长券、优惠券、额度等
  • 在线时长由节点统计（v3.7.0 起）— 不再由客户端上报；用户挂着不用 VPN 不会累积时长
  • 每日上限：单日在线时长封顶 2 小时；30 分钟墙钟宽限期；并发结算已加锁防重复领取
  • 累计参与：约 1,772 次抽奖（接手以来累计）
  • Rule: free users earn a draw after a daily connect-time threshold; prize pool includes plan vouchers, coupons, free-quota credits
  • Time counted by node (v3.7.0+) — no longer reported by client; users idling on a paused VPN don't accumulate time
  • Daily caps: 2-hour hard cap per day; 30-min wall-clock grace; concurrent-settle race protected with a Lua lock
  • Participation: ~1,772 draws (cumulative since handover)

优惠券Coupons

  • 当前模板数：~78 个（覆盖新人 / 活动 / 老客户挽回 / 客服补偿等场景）
  • 可发放：用户列表批量发放、单用户后台手动发放
  • 使用约束：每张券绑定套餐适用范围 + 有效期 + 单用户次数，BA 在创建模板时指定
  • Templates today: ~78 (new-user / campaign / win-back / support-comp scenarios)
  • Issuance: bulk via user list, or single-user manual from admin
  • Constraints: each coupon binds plan eligibility + validity window + per-user limit, set at template creation

推荐 / 邀请码Referral / Invite Code

  • 累计推荐人：约 912 个有效推荐人
  • 奖励逻辑：被推荐人首次付费 → 推荐人获得佣金（钱包余额）
  • 测试环境功能开关关闭，QA 测推荐流程会失败属正常
  • Active referrers: ~912 cumulative
  • Reward: when referred user makes first payment → referrer earns commission (wallet credit)
  • Disabled in staging; QA failures on referral flow are expected, not a bug
