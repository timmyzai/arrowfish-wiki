从 Arrowfish 到 FFF — 产品演进故事

From Arrowfish to FFF — Product Evolution Story

适合：全体团队成员 For: All team members
这份文档帮助所有人理解：我们为什么要做 FFF、Arrowfish 的去向，以及这个决定对每个人意味着什么。
This document helps everyone understand: why we're building FFF, where Arrowfish is heading, and what this decision means for each of us.

一、背景：我们从哪里接手1. Background: What We Inherited

2026年3月，我们从台湾外包团队完成了项目交接。原本计划25个工作日完成的交接，被压缩到了 4 天。

In March 2026 we completed handover from the Taiwan outsourced team. The original 25-working-day handover plan was compressed into 4 days.

这意味着：我们在信息高度不完整的情况下，接管了一个有约 32.5 万注册用户、156 个全球节点、每月约 ¥3.5 万收入的线上运营服务。

This meant: with severely incomplete information, we took over a live operating service with ~325K registered users, 156 global nodes, and ~¥35K monthly revenue.

接手的不只是代码，而是一个正在运行的业务——包括它的历史债务、不稳定节点、不完整文档和正在流失的用户。
What we inherited was not just code, but a running business — along with its historical debt, unstable nodes, incomplete documentation, and churning users.

二、Arrowfish 的现状2. Arrowfish: Current State

做得好的地方What works well

  • 核心 VPN 连接功能可用，有真实付费用户（约 1,369 人）
  • 支付体系完整，微信/支付宝/USDT/IAP 全覆盖
  • 后台管理系统（BO）功能齐全
  • 有完整的会员套餐体系
  • Core VPN connection works, with real paying users (~1,369)
  • Complete payment stack: WeChat / Alipay / USDT / IAP all covered
  • Backoffice (BO) admin system is feature-complete
  • Complete membership plan structure

需要正视的问题Problems we need to face

  • 架构碎片化——Android 原生、PC 端 sing-box、iOS 端 HiYou SSH 三套独立实现，互不复用，任何功能改动都要维护三份
  • 技术债严重——接手后第一个月就发现并修复了 49+ 个安全和稳定性问题
  • 用户流失严重——月活从 2.9 万（10月）降至 1.5 万（3月），新用户第2个月留存率约 10%
  • 节点频繁中断——是用户 #1 投诉，节点稳定性是最核心痛点
  • 代码无法复用——Arrowfish 的任何新功能都无法直接带到下一代产品
  • Fragmented architecture — three separate implementations (native Android, sing-box on PC, HiYou SSH on iOS) share nothing; every feature change must be maintained three times
  • Heavy tech debt — found and fixed 49+ security and stability issues in the first month after takeover
  • Severe user churn — MAU dropped from 29K (Oct) to 15K (Mar); month-2 retention for new users sits around 10%
  • Frequent node outages — the #1 user complaint; node stability is the single biggest pain point
  • Code can't be reused — no new feature built on Arrowfish can be carried over to the next-gen product

三、为什么需要 FFF3. Why FFF

核心原因：Arrowfish 是原生 Android，FFF 是跨平台 Flutter。两者架构根本不同，在 Arrowfish 上做的任何功能都无法带到 FFF。
Core reason: Arrowfish is native Android, FFF is cross-platform Flutter. The architectures are fundamentally different — nothing built on Arrowfish carries over to FFF.

继续大量投入 Arrowfish 新功能，等于把资源投进一个即将被替换的系统。这会造成双重浪费：

Pouring more new features into Arrowfish means investing in a system about to be replaced. This creates double waste:

  • 开发资源浪费在无法复用的代码上
  • 用户对 Arrowfish 新功能产生依赖，迁移反而更难
  • Engineering effort spent on code that can't be reused
  • Users grow dependent on Arrowfish-only features, making migration harder

同时，业务上也有迫切需求：

At the same time, the business has urgent needs:

  • 需要覆盖 iOS 用户（当前 iOS 客户端 HiYou SSH 已停止更新，开发者账号被封，无法继续发版）
  • 需要覆盖 PC（macOS / Windows）用户
  • 需要在新公司主体下运营（欧盟合规要求）
  • 需要从第一天起就做好无日志合规架构
  • Cover iOS users (the current iOS client HiYou SSH is no longer updated; the developer account is banned and can't ship new releases)
  • Cover PC (macOS / Windows) users
  • Operate under a new corporate entity (EU compliance requirement)
  • Build a no-logs compliant architecture from day one

五、两个产品如何并存5. How Both Products Coexist

在 FFF 上线之前，Arrowfish 和 FFF 会并行运行。用户数据不会自动迁移，用户需要主动下载 FFF 并重新注册或迁移账号。

Until FFF goes live, Arrowfish and FFF run in parallel. User data does not migrate automatically — users must download FFF themselves and either re-register or migrate their account.

Arrowfish will not be shut down abruptly. Both products coexist through the transition; user migration is gradual, not a forced switch.
